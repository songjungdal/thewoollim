# 어울림 멤버십 결제 페이지 (자동결제 심사용, 테스트 키) — 1-A단계 명세

> 2026-10-22 사용자 요청으로 받은 명세를 보관한 것이다. 자동결제 MID 이름은 `[민감정보 생략]` 으로 가렸다.
> 구현: `app/membership/`, `app/mypage/MembershipSection.tsx`, `app/lib/membership.ts`, `api/membership/`.
> 명세와 다르게 구현한 점은 맨 아래 "구현 메모"에 적는다.

## 배경
토스페이먼츠 일반 결제는 승인 완료, 자동결제(빌링)는 심사 중.
심사를 위해 실제 사이트(thewoollim.com)에서 멤버십 상품 페이지와 카드 등록(자동결제) 결제창이 동작해야 한다.
개발자센터에 자동결제용으로 보이는 MID([민감정보 생략])가 생성돼 있다. 이 MID의 API 개별 연동 테스트 키(test_ck_…, test_sk_…)로 먼저 연동하고, 계약 미완료로 카드 등록창이 오류를 내면 "개발 연동 체험 상점"의 테스트 키로 바꿔 연동한다.
테스트 키 결제는 실제로 청구되지 않는다.

## 작업 전 확인
1. 기존 결제 연동 방식과 키 종류(결제위젯/결제창 gck 계열인지, API 개별 ck 계열인지)를 확인하고 요약. 기존 결제 키·코드는 수정 금지.
2. 회원·로그인·본인인증 구조, 공통 레이아웃·하단(footer), 마이페이지 구조 확인.

## 유지할 기능 (회귀 금지)
- 회원가입, 로그인, 본인인증, 기존 파티 신청·단건 결제·장바구니·쿠폰·취소·환불, 관리자 기능

## 1) 환경변수 (기존 결제 키와 분리)
- TOSS_BILLING_CLIENT_KEY, TOSS_BILLING_SECRET_KEY : 자동결제 MID의 테스트 키 (오류 시 체험 상점 테스트 키). 기존 일반 결제 MID 키와 혼용 금지
- TOSS_BILLING_MODE : test | live (지금은 test)
- 시크릿 키는 서버 환경변수/AWS Secrets Manager에만. 저장소·프론트 번들·로그 노출 금지

## 2) 데이터
- memberships: id, user_id, status(pending|active|canceled|expired), price, customer_key, billing_key(암호화), card_company, card_last4, current_period_start, current_period_end, next_billing_at, cancel_at_period_end, canceled_at, is_test, created_at
- membership_payments: id, membership_id, cycle_no, order_id(고유), payment_key, amount, status(success|failed|refunded), fail_code, fail_message, approved_at, raw_response, is_test
- 회원당 진행 중 멤버십 1건만 허용
- TOSS_BILLING_MODE=test에서 만든 멤버십은 is_test=true, 어떤 혜택도 주지 않음

## 3) 페이지 (메인·상단 메뉴·파티 화면에 링크 넣지 않음, meta robots noindex, 사이트맵 제외)
### /membership/ 소개
- 첫 화면: 상품명 "어울림 멤버십", 가격 "월 99,000원"
- 내용: 매칭파티·솔로파티 중 본인 조건(나이·싱글/돌싱·성별 정원)에 맞는 파티를 추가 참가비 없이 신청
- 이용 규칙 요약: 동시에 보유 가능한 예약 2건, 파티별 멤버십 좌석 수 제한, 파티 2일 전부터의 취소·노쇼 시 예약 제한
- 결제 안내: 가입일에 첫 결제, 이후 매월 같은 날 등록 카드로 자동결제, 국내 발급 카드만 가능
- 해지·환불 요약: 마이페이지에서 언제든 해지(이미 결제한 기간 끝까지 이용), 결제 후 7일 이내·미사용 시 전액 환불
- 이미지: 기존 현장 사진 활용, 깨지거나 같은 이미지 반복 금지
- "멤버십 시작하기" 버튼 → /membership/join/
### /membership/join/ (로그인 필요, 비로그인 시 로그인 후 이 페이지로 복귀)
- 결제 금액 99,000원, 오늘 결제 / 다음 결제일 표시
- 필수 동의 3개(미리 체크 금지, 모두 체크해야 버튼 활성): 멤버십 이용약관, 정기결제(자동결제) 동의, 환불 규정. 각 항목 "보기" 링크
- "카드 등록하고 시작하기" → 토스 SDK v2: TossPayments(clientKey).payment({ customerKey }).requestBillingAuth({ method: "CARD", successUrl, failUrl, customerEmail, customerName })  (파라미터는 토스 SDK 레퍼런스 기준으로 확인)
- customerKey: 회원별 고정, 추측 불가 무작위 값(UUID 등), 개인정보 미포함
### /membership/success/
1. 쿼리의 customerKey가 로그인 회원의 값과 같은지 검증 (다르면 거부)
2. POST https://api.tosspayments.com/v1/billing/authorizations/issue  { authKey, customerKey } → billingKey 암호화 저장
3. POST https://api.tosspayments.com/v1/billing/{billingKey}  { customerKey, amount: 99000, orderId(고유), orderName: "어울림 멤버십 (월간)", customerEmail, customerName }
4. 성공: status=active, 기간·다음 결제일 기록, 결제 금액·카드사·끝 4자리·다음 결제일 표시
5. 실패: fail 페이지, 결제 안 된 빌링키는 삭제 API로 삭제
- 새로고침·중복 호출 시 중복 발급·중복 결제가 일어나지 않도록 처리
### /membership/fail/
- 토스 에러 코드·메시지를 사용자 문구로 안내 + "다시 시도" 버튼
### 마이페이지 > 멤버십 (간단)
- 상태, 이용 기간, 다음 결제일·금액, 카드사·끝 4자리, 결제 내역
- "해지하기": 확인 1회 → cancel_at_period_end=true, "해지 취소" 가능
- 해지 버튼은 다른 버튼과 같은 크기, 같은 화면

- /refund/ 에 "멤버십(정기결제) 해지·환불" 섹션 추가 (아래 ⑤⑥⑦⑨ 내용 요약)
- 기존 조항 번호가 바뀌지 않도록 새 조항은 마지막(부칙 앞)에 추가

### 멤버십 조항 초안 ("제15조 멤버십(정기결제) 서비스")
① "멤버십"은 회원이 매월 정해진 요금을 자동결제하고, 이용 기간 동안 회사가 정한 조건에 맞는 파티에 별도 참가비 없이 참여를 신청할 수 있는 서비스입니다.
② 이용 요금은 월 99,000원입니다. 가입일에 첫 결제가 이루어지고, 이후 매월 같은 날 회원이 등록한 카드로 자동결제됩니다. 해당 날짜가 없는 달은 그달 말일에 결제됩니다.
③ 이용 기간은 결제일부터 다음 결제일 전날까지입니다.
④ 멤버십으로 참여할 수 있는 파티, 파티별 멤버십 좌석 수, 동시에 보유할 수 있는 예약 수 등 세부 이용 조건은 멤버십 안내 페이지에 게시합니다.
⑤ 회원은 마이페이지에서 언제든지 멤버십을 해지할 수 있습니다. 해지하면 다음 결제부터 청구되지 않으며, 이미 결제한 이용 기간이 끝날 때까지 이용할 수 있습니다.
⑥ 결제일로부터 7일 이내이고 해당 이용 기간에 멤버십으로 파티를 예약하거나 참여한 이력이 없는 경우 전액 환불하며, 이때 멤버십은 즉시 종료됩니다. 그 밖의 경우 해당 이용 기간의 요금은 환불되지 않습니다.
⑦ 자동결제가 실패하면 회사는 회원에게 알리고 재결제를 시도합니다. 재결제가 이루어지지 않으면 멤버십은 종료되며, 종료일 이후의 멤버십 예약은 취소됩니다.
⑧ 회사가 이용 요금을 인상하는 경우 인상 전에 회원에게 알리고 별도의 동의를 받으며, 동의하지 않은 회원에게는 인상된 요금으로 결제하지 않습니다.
⑨ 파티 2일 전부터 멤버십 예약을 취소하거나 참석하지 않은 경우 운영정책에 따라 일정 기간 멤버십 예약이 제한될 수 있습니다.

## 구현 메모 (명세와 다르게 정한 점)

- **키 위치**: 환경변수·AWS Secrets Manager 대신 서버의 `api/payments/toss-billing-config.php` 파일에 둔다(사용자 결정, 2026-10-22). 항목 이름은 명세의 환경변수 이름과 같게 했고, 빌링키 암호화 키 `TOSS_BILLING_ENC_KEY` 를 더했다. 값이 비었거나 형식이 틀리면(test 모드에 live 키, gck 키, 일반 결제 키와 같은 값 등) "준비 중"으로 보이고 결제를 시작하지 않는다.
- **데이터 저장**: DB 테이블 대신 기존 예약처럼 JSON 파일에 둔다(사용자 결정). memberships·membership_payments 를 한 파일(`membership/memberships-<해시>.json`)에 함께 두고 파일 잠금 안에서만 읽고 쓴다. 2026-10-22 부터 이 파일은 **웹 루트 밖 데이터 폴더에만** 저장하고(`.htaccess` 에 기대지 않음, 사용자 요청), 그 폴더가 없으면 "준비 중"이다. 명세 항목 외에 `auth_key_hash`, `pending_order_id`, `billing_anchor_day`, `updated_at`, `fail_code`·`fail_message`(멤버십), `billing_key_deleted` 를 둔다.
- **첫 결제 실패**: 빌링키를 삭제하고 멤버십 상태를 `canceled` 로 둔다(명세 상태값 안에서 처리).
- **결제 결과를 모를 때**(통신 끊김·5xx): 멤버십을 `pending` 으로 두고, 다시 확인하면 같은 주문번호로 토스 "orderId 로 결제 조회"를 먼저 한 뒤 없을 때만 같은 주문번호로 다시 결제한다. 결제 요청에는 주문번호를 `Idempotency-Key` 로 보낸다.
- **마이페이지 멤버십 영역**은 멤버십 기록이 있는 회원에게만 보인다(아직 공개하지 않는 상품이라 다른 회원에게 노출하지 않기 위해).
- **로그인 후 복귀**는 `?redirect=/membership/…` 일 때만 한다. 다른 화면은 기존 정책(메인으로 이동)을 그대로 둔다.
