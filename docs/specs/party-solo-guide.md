## 1. 작업 목적

솔로파티는 MC가 진행하는 단체 파티다. 게임을 하고 술도 마시는, 매칭파티(소개팅)보다 **동적인 자리**다. 지금은 상세페이지와 신청 흐름이 매칭파티 기준이라 솔로파티와 맞지 않는다. 다음 세 가지를 바꾼다.

1. **프로필 카드 단계 없애기:** 솔로파티는 프로필 카드(직업·MBTI·관심사 등)를 받지 않는다. 이름·나이·성별은 가입할 때 본인인증과 필수 정보 입력으로 이미 받고 있으므로, **회원이 추가로 쓸 것은 없다.**
2. **안내 문구 바꾸기:** 상세페이지의 "신청 전 꼭 확인해주세요", "참가 신청 방법", "필수 확인 사항"을 솔로파티용 문구로 보여준다.
3. **소개글 추가:** 파티마다 관리자가 쓰는 상세페이지형 소개글(소제목·본문·사진 묶음)을 참가 항목 선택 아래에 보여준다.

**매칭파티 화면·흐름·문자는 바뀌지 않는다.** 소개글은 두 종류 모두 쓸 수 있지만, 비어 있으면 화면에 아무것도 나오지 않는다.

## 2. 운영 방식 (대표 확정, 2026-10-10)

| 항목 | 결정 |
|---|---|
| 참가 확정 | 결제(무통장은 입금 확인) 즉시 **[확정 대기 중]**. 관리자가 [참가확정]을 누르면 확정 문자가 나간다. 프로필 단계만 빠진다 |
| 안내 문구 | **솔로파티 공통 문구로 고정**한다. 파티마다 다른 내용은 소개글에 쓴다 |
| 소개글 형태 | **소제목 + 본문 + 사진 여러 장**을 한 묶음으로, 묶음을 여러 개 쌓는 상세페이지 형태 |

## 4. 프로필 카드 단계 없애기 (솔로파티)

### 4-1. 규칙

- **솔로파티 예약은 결제 즉시 `pending_approval`**(무통장은 입금 확인 즉시)로 만든다. 직업·MBTI가 비어 있어도 그렇다.
- 매칭파티 예약은 지금 규칙(프로필 완성 여부) 그대로다.
- 상태는 **예약마다** 정한다. 한 번에 매칭파티와 솔로파티를 함께 결제하면 각자 자기 규칙을 따른다.
- 파티 종류는 결제 시점 `parties.json`의 값으로 판단한다(`partyTypeOf`).

### 4-2. 서버 변경

| 파일 | 변경 |
|---|---|
| `api/payments/success.php` | `$initialStatus` 하나 대신 예약마다 상태를 정한다. 솔로파티면 `pending_approval`, 매칭파티면 지금 규칙. `profileNotifiedAt` 기록과 프로필 안내 문자는 `paid_pending_profile` 예약에만, 신청 접수 문자(`notifyPendingSms`)는 `pending_approval` 예약에만 보낸다 |
| `api/admin/bookings.php` `confirm_vbank` | 그 예약의 파티가 솔로파티면 `pending_approval`. 그 밖에는 지금 규칙 |
| `api/party-participants.php` | 솔로파티 참가자는 `mbti`·`job`을 빈 값으로 내려준다(이름 가림·연령대·항목 이름만) |

- `api/profile.php`, 관리자 `approve`, 프로필 안내 문자 2종은 바꾸지 않는다. 솔로파티 예약은 `paid_pending_profile`이 되지 않으므로 자연스럽게 빠진다.
- 배포 전에 이미 `paid_pending_profile`로 만들어진 솔로파티 예약이 있으면, 관리자가 [참가확정]으로 바로 확정할 수 있다. 데이터 변환은 하지 않는다.

### 4-3. 화면 변경

| 화면 | 변경 |
|---|---|
| 결제완료(`app/payment/success/page.tsx`) | 이번 주문이 **모두 솔로파티**면 "잠시만요! 프로필 카드 작성" 박스와 나가기 확인 창을 띄우지 않는다. 대신 안내 박스를 보여준다: "결제가 완료되었습니다. 관리자 확인 후 **참가 확정 문자**를 보내드립니다. 별도의 프로필 작성은 필요 없습니다." 매칭파티가 하나라도 섞여 있으면 지금과 같다 |
| 마이페이지 | 바꿀 것 없음(상태 기준으로 이미 동작). 솔로파티 예약에 [프로필 카드 작성] 버튼이 나오지 않는지만 확인한다 |
| 상세 실시간 참가 인원 | 솔로파티는 MBTI·직업 칸을 그리지 않는다 |

## 5. 안내 문구를 파티 종류별로

### 5-1. 구조

- 상세페이지에 고정된 세 영역을 **종류별 문구**로 바꾼다.
  - "신청 전 꼭 확인해주세요" 박스
  - "참가 신청 방법" 단계
  - "필수 확인 사항" 목록
- 문구는 새 파일 `app/lib/partyGuides.ts`에 `{ matching, solo }`로 둔다. **매칭파티 문구는 지금 코드의 문구를 한 글자도 바꾸지 않고 옮긴다.**
- 종류는 상세 안내(`shownDetail`)와 같은 판단을 쓴다. 종류가 확인되기 전에 매칭파티 문구가 잠깐 보였다가 바뀌는 일이 없게 한다.
- 화면 모양(카드, 번호, ⚠ 경고 줄, 참고 박스)은 지금 그대로 쓴다.

### 5-2. 솔로파티 문구

6장의 문구를 그대로 넣는다.

## 6. 솔로파티 문구 (초안 — 대표 확인 후 수정 가능)

### 6-1. 신청 전 꼭 확인해주세요

> 솔로파티는 MC 진행에 따라 게임과 대화를 즐기는 **단체 파티**입니다. 결제하시면 **[확정 대기 중]** 상태가 되며, 운영진이 성비와 참가 조건을 확인한 뒤 **[참가 확정]** 문자를 보내드립니다. 별도의 프로필 카드 작성은 필요 없습니다.

### 6-2. 참가 신청 방법

| 단계 | 제목 | 설명 | 참고 박스 |
|---|---|---|---|
| 1 | 파티 확인하고 결제하기 | 일시·장소·참가 대상을 확인하고, 참가 항목(1부·2부 등)이 있다면 원하는 항목을 골라 결제해 주세요. | 없음 |
| 2 | 참가 확정 문자 확인하기 | 결제하시면 [확정 대기 중] 상태가 되고, 운영진 확인 후 참가 확정 문자를 보내드립니다. 별도의 프로필 작성은 필요 없습니다. | 마이페이지의 내 예약 현황에서 참가 확정 여부를 확인하실 수 있습니다. |
| 3 | 신분증 챙겨서 방문하기 | 참가가 확정되면, 신청하신 파티(회차) 시작 시각에 맞춰 신분증을 지참하고 방문해 주세요. | 성비가 맞지 않거나 주최측의 사정으로 파티가 취소될 경우 100% 환불이나 쿠폰 적립 후 다음 모임 선확정 중 선택하실 수 있습니다. |

- 3단계 참고 박스는 매칭파티와 같은 문구다(환불 규정이 같으므로).

### 6-3. 필수 확인 사항

머리말: "모두가 즐겁고 안전한 파티를 위해 아래 내용을 꼭 확인해 주세요."

| 번호 | 제목 | 설명 | ⚠ 경고 |
|---|---|---|---|
| 1 | 신분증 지참 (본인·성인 확인) | 술과 함께하는 파티로, 입장 시 신분증으로 본인 여부와 성인 여부를 확인합니다. 신분증(주민등록증, 운전면허증 등)을 꼭 지참해 주세요. | 미지참 시 입장이 제한될 수 있으며, 이로 인한 환불은 불가합니다. |
| 2 | 드레스코드 — 깔끔하고 편안한 캐주얼 | 게임과 활동이 있는 파티입니다. 깔끔하면서도 움직이기 편한 캐주얼 복장을 권장합니다. | 트레이닝복, 슬리퍼 등 과하게 편안한 복장은 입장이 제한될 수 있습니다. |
| 3 | 건강한 음주 매너 | 음주는 자율입니다. 자신의 주량에 맞게 즐겨 주시고, 다른 분께 술을 권하거나 강요하지 말아 주세요. 음주 후에는 절대 운전하지 마시고 대중교통이나 대리운전을 이용해 주세요. | 과도한 음주로 다른 참가자에게 불편을 주는 경우 즉시 퇴장 조치되며, 참가비는 환불되지 않습니다. |
| 4 | 서로를 존중하는 매너 | 게임 중에도 상대방이 불편해하는 신체 접촉이나 언행은 삼가 주세요. 불편한 상황이 생기면 언제든 MC나 운영진에게 말씀해 주세요. | 위반 시 운영진 판단에 따라 즉시 퇴장 조치되며, 참가비는 환불되지 않습니다. |
| 5 | 신청한 회차 시간 지키기 | 신청하신 회차의 시작 시각에 맞춰 입장해 주세요. 신청하지 않은 회차에는 참여할 수 없습니다. | 없음 |
| 6 | 신중한 참가 신청 | 파티는 정해진 성비를 맞추어 세심하게 준비됩니다. 당일 무단 불참(No-Show)은 다른 참가자분들의 즐거운 시간을 해치므로 신중한 참가 신청을 부탁드립니다. | 무단 불참 시 향후 모든 파티 참여가 제한될 수 있습니다. |
| 7 | 현장 기록 및 마케팅 활용 안내 | (매칭파티 5번과 같은 문구) | 없음 |

- 5번은 참가 구성(회차)이 **있는 파티에서만** 보여준다. 회차가 없는 솔로파티는 6개만 보여준다.

## 7. 소개글

### 7-1. 데이터 (`detail.about`)

기존 파티별 상세 안내(`detail`)에 `about`을 추가한다. 기존 `timeline.intro`(진행 안내 소개 문구)와 헷갈리지 않게 이름을 `about`으로 한다.

```ts
about: {
  title: string;               // 영역 제목. 기본 "파티 소개" (40자 이하)
  sections: {
    heading: string;           // 소제목 (40자 이하, 비워도 됨)
    body: string;              // 본문 (2,000자 이하, 줄바꿈 유지, 비워도 됨)
    images: { url: string; alt: string }[];  // 사진 0~10장. 주소 규칙은 기존 사진 칸과 같다
  }[];                         // 0~10개
}
```

- 묶음 하나에는 소제목·본문·사진 중 **하나 이상**이 있어야 한다. 셋 다 비면 저장 때 거절한다.
- 서버: `api/lib.php` `sanitizePartyDetail`에서 위 제한과 사진 주소 규칙(`/uploads/parties/…`, `/images/…`만)을 검사한다. 본문은 글자로만 다루고 HTML로 해석하지 않는다.
- `about`이 없는 기존 파티는 "묶음 0개"로 본다. 데이터 변환은 하지 않는다.
- 종류별 기본 내용(템플릿)의 `about`은 매칭·솔로 모두 비워 둔다.
- 공개 조회 `/api/party-detail.php`가 `about`을 함께 내려준다. 파티 목록 API에는 넣지 않는다(지금 `detail` 규칙과 같음).

### 7-2. 상세페이지 위치·모양

- 위치: **참가 항목 선택과 [참가하기]·[장바구니] 버튼 바로 아래**, "실시간 참가 인원"과 사진 ①(참가 신청 방법 위)보다 위.
- 묶음이 0개면 영역 전체를 그리지 않는다. 그래서 소개글이 없는 매칭파티는 지금과 똑같이 보인다.
- 모양
  - 다른 영역과 같은 폭(`max-w-4xl`)과 같은 제목 스타일(아이콘 + 제목)을 쓴다.
  - 묶음마다 소제목 → 본문 → 사진 순서로 보여준다.
  - 본문은 줄바꿈을 그대로 살린다.
  - 사진은 기존 상세 사진처럼 폭에 꽉 차게, 비율을 지키며 세로로 나열한다.
  - 모바일 375px, PC 1280px 모두 확인한다.

### 7-3. 관리자 화면

- 파티 등록·수정 창의 상세페이지 안내 편집기(`PartyDetailEditor.tsx`) 맨 위에 **"소개글"** 영역을 둔다.
  - 영역 제목 입력칸(기본 "파티 소개")
  - 묶음마다: 소제목, 본문(여러 줄), 사진 올리기(기존 업로드 기능 사용, 여러 장), 위로/아래로, 삭제
  - 아래에 [+ 소개 묶음 추가] 버튼
- [다른 파티에서 불러오기]를 하면 소개글도 함께 불러온다.
- 기존 "내용 (소개)" 입력칸 이름을 **"한 줄 소개 (제목 아래 표시)"**로 바꾼다. 동작은 그대로다.

## 8. 변경하지 않는 것 (회귀 금지)

- 매칭파티의 상세페이지 화면(문구 한 글자까지), 결제 후 상태 규칙, 프로필 작성 흐름, 문자
- 참가 구성(회차·항목), 정원, 결제·환불·취소 로직
- 예약 상태값 8종과 전환 규칙(솔로파티가 `paid_pending_profile`을 거치지 않는 것만 바뀜)
- 가입·온보딩·본인인증 흐름, 참가 자격 검사
- 운영 데이터 직접 수정 금지, 배포 보호 규칙

## 9. 확인할 것 (개발과 별도로 대표에게)

- **2시간 전 안내 문자:** "시작 20분 전부터 라운지 입장, 차 한잔" 문구는 매칭파티 장소 기준이다. 솔로파티 장소·입장 규칙이 다르면 솔로파티용 문구를 따로 정해 이 작업에 추가한다. 정해지기 전에는 바꾸지 않는다.

## 10. 테스트 및 완료 기준

**신청 흐름** (모의 토스·모의 알리고)
- [ ] 직업·MBTI가 비어 있는 회원이 솔로파티를 카드 결제하면 바로 `pending_approval`이 되고, 신청 접수 문자가 가며, 프로필 안내 문자는 가지 않는다(`profileNotifiedAt` 없음).
- [ ] 같은 회원이 매칭파티를 결제하면 지금처럼 `paid_pending_profile`이 된다.
- [ ] 매칭파티와 솔로파티를 한 번에 결제하면 각 예약이 자기 규칙대로 상태와 문자를 받는다.
- [ ] 솔로파티 무통장 [결제확인]도 바로 `pending_approval`이다.
- [ ] 관리자 [참가확정]이 솔로파티 예약에서 정상 동작한다.
- [ ] 솔로파티만 결제한 결제완료 화면에 프로필 박스와 나가기 확인 창이 나오지 않고, 솔로파티 안내가 나온다. 섞여 있으면 지금과 같다.

**상세페이지** (375px·1280px)
- [ ] 솔로파티 상세에 "프로필"이라는 말이 나오지 않는다. 세 영역이 6장 문구로 나온다.
- [ ] 회차가 없는 솔로파티는 필수 확인 사항 5번이 빠진다.
- [ ] 솔로파티 실시간 참가 인원에 MBTI·직업이 나오지 않는다.
- [ ] **매칭파티 상세는 변경 전과 픽셀 단위로 같다**(소개글 없을 때).

**소개글**
- [ ] 관리자에서 묶음 3개(사진 포함)를 넣고 저장하면, 상세의 참가 항목·버튼 바로 아래에 순서대로 나온다.
- [ ] 묶음 순서 바꾸기·삭제가 저장에 반영된다.
- [ ] 제한을 넘거나(묶음 11개, 본문 2,001자, 사진 11장), 허용되지 않은 사진 주소, 빈 묶음은 서버가 거절한다.
- [ ] 본문에 `<script>` 같은 글자를 넣어도 글자 그대로 보인다.
- [ ] [다른 파티에서 불러오기]로 소개글이 복사된다.
- [ ] 소개글이 없는 파티는 영역이 보이지 않는다.

**공통**
- [ ] `npm run lint`·`npm run build` 통과
- [ ] 결제 회귀, 솔로 서버, 참가 구성, 관리자 화면 테스트 모두 통과
- [ ] `docs/PROJECT_OVERVIEW.md` 갱신 (사용자 흐름, 예약 상태, 상세페이지 구성, 관리자 기능)

## 11. 작업 순서와 배포
