# 대관료 결제 링크 개발 명세서

- 작성일: 2026-11-03
- 기준 코드: `songjungdal/thewoollim` main `2c73188`
- 대상: 관리자 대시보드(새 탭), 결제 페이지 `/pay/`(사이트 메뉴에 노출하지 않음), 결제 처리 PHP API

---

## 0. 목적과 결정 사항

어울림 장소 대관료를 받을 **개인 결제 링크**를 만든다. 사이트 메뉴나 화면에는 띄우지 않는다. 관리자가 대관 건마다 링크를 만들어 문자·카톡으로 보내면, 받은 사람이 링크를 열어 바로 결제한다.

| 항목 | 결정 |
|---|---|
| 금액 | **관리자가 링크마다 정한다.** 결제자는 금액을 바꿀 수 없다 |
| 링크 | **1회용.** 대관 1건에 링크 1개. 결제가 끝나면 다시 결제할 수 없다 |
| 결제 수단 | 카드·간편결제 (지금 파티 결제와 같은 토스 결제창) |
| 환불 | **파티와 같은 환불 규정**(이용일 기준 5일 전 100% / 4일 전 80% / 3일 전 50% / 2일 전~당일 불가)을 결제 전에 보여주고 동의를 받는다. 취소는 관리자가 [전액 취소]/[부분 취소]로 처리하며, 화면에 규정상 환불 금액을 계산해 보여준다 |
| 금액 상한 | 링크 1건당 **2,000,000원** |
| 토스 상점 | 대관 겸 파티 진행이므로 기존 토스 상점으로 받는다 (대표님 확인 2026-11-03) |
| 회원가입 | **필요 없음.** 로그인 없이 결제 |
| 노출 | 메뉴·사이트맵·검색에 노출하지 않음. 링크를 가진 사람만 열 수 있음 |

## 1. 현재 구현 상태 (코드 확인 결과)

- 파티 결제: `app/checkout/page.tsx`에서 토스 결제위젯 v2(`NEXT_PUBLIC_TOSS_CLIENT_KEY`) → `api/payments/pending.php`(주문 생성, **로그인 필수**) → 토스 결제창 → `api/payments/success.php`(금액 검증 + 토스 승인 + 예약 생성)
- 토스 서버 키: `api/payments/toss-config.php` (서버에만 있음)
- 결제 취소: `api/admin/bookings.php`가 토스 취소 API에 `cancelAmount`를 보내는 방식으로 이미 쓰고 있음
- 지금은 **로그인 없이 결제하는 기능과 파티가 아닌 결제가 없다.** 이번에 새로 만든다
- 운영자 텔레그램 알림: `api/notify/_telegram.php` `telegramSend()` (PR #118·#119)
- 관리자 활동 기록: `api/admin/_session.php` `logAdminActivity()`

**기존 파티 결제 코드(`pending.php`, `success.php`, `fail.php`, `vbank-submit.php`, `checkout`)는 수정하지 않는다.** 결제 링크는 별도 파일로 만든다.

## 2. 관리자 화면: 새 탭 "결제 링크"

### 2-1. 목록

- 최근 만든 순. 필터: 상태(전체/결제 대기/결제 완료/취소/만료·중지), 월
- 각 줄: 링크 번호, 결제명, 금액, 상태 배지, 결제 기한, 만든 날짜, 결제 일시
- 상단 요약: 이번 달 결제 완료 건수·금액 / 취소 금액

### 2-2. [새 결제 링크 만들기]

| 항목 | 필수 | 규칙 |
|---|---|---|
| 결제명 | 필수 | 결제창·영수증에 그대로 보임. 2~40자. 예: "11/20(목) 대관 및 파티 진행" |
| 금액 | 필수 | 1,000원 ~ **2,000,000원**, 원 단위 정수 (화면·서버 모두 검사) |
| 이용일 | 필수 | 날짜(YYYY-MM-DD). **환불 규정 계산 기준일.** 오늘 이후만 |
| 이용 시간·장소 | 선택 | 결제 페이지에 표시. 100자 이내. 예: "19:00~23:00 · 미금역 어울림 라운지" |
| 결제자 이름 | 선택 | 결제 페이지 이름 칸에 미리 채움 |
| 결제자 연락처 | 선택 | [문자로 보내기]에 사용 |
| 추가 안내 | 선택 | 환불 규정 아래에 덧붙일 문구(인원·준비물 등). 500자 이내 |
| 결제 기한 | 필수 | 기본 7일 뒤 23:59, 최대 30일. **이용일보다 늦을 수 없음** |
| 관리자 메모 | 선택 | 관리자만 봄 |

환불 규정은 입력받지 않고 **파티 환불 규정을 그대로** 보여준다 (3-1).

- 결제명 입력칸 아래 안내: "결제명은 결제자에게 보이며 운영자 텔레그램 알림에도 표시됩니다."
- 저장하면 링크가 만들어지고 **[링크 복사]** 버튼과 링크 주소가 보인다

### 2-3. 링크 상세

- 위 입력값, 상태, 결제 정보(결제 수단, 승인 일시, 결제자 이름·연락처, 영수증 보기), 취소 이력
- 버튼
  - **[링크 복사]**
  - **[문자로 보내기]**: 연락처가 있을 때만. 확인창 후 알리고로 발송.
    문구: `[어울림] {결제명} 결제 요청드립니다.\n금액: {금액}원\n결제 기한: {MM/DD HH:mm}\n{링크}`
  - **[링크 중지]**: 결제 대기일 때만. 중지하면 링크로 결제 불가. [다시 열기]로 되돌릴 수 있음(기한 안에서)
  - **[수정]**: 결제 대기일 때만. 금액·결제명·이용일·이용 시간·장소·추가 안내·기한 수정 가능. **결제 진행 중(4-1의 주문이 살아 있는 10분)에는 수정 불가**
  - **[전액 취소]**, **[부분 취소]**: 결제 완료일 때만. 취소 사유 필수, 부분 취소는 금액 입력(남은 결제 금액 이하). 확인창: "{금액}원을 취소할까요? 결제자 카드로 환불됩니다."
    - 취소 창 위에 **"오늘 기준 규정: 이용일 {N}일 전 · {비율} 환불 → {금액}원"** 을 표시하고, 부분 취소 금액 칸에 이 금액을 미리 채운다. 관리자가 바꿀 수 있다(예: 운영 사정으로 전액 환불)
    - 규정 금액과 다르게 취소하면 사유에 그 이유를 적도록 안내
  - 삭제 기능은 만들지 않는다(결제 기록 보존). 결제 전 링크는 [링크 중지]로 정리
- 만들기·수정·중지·문자 발송·취소는 모두 기존 관리자 활동 로그에 남긴다

## 3. 결제자 화면: `/pay/?t=<링크 코드>`

- 링크 코드: 서버가 만드는 **추측할 수 없는 무작위 32자**. 순번(1, 2, 3…)으로 열 수 없어야 함
- `noindex`, `public/robots.txt`에 `Disallow: /pay/` 추가, 사이트맵 제외, 메뉴·푸터 링크 없음
- 로그인·온보딩 강제 이동 대상에서 제외 (`app/components/OnboardingGuard.tsx`의 허용 경로에 `/pay` 추가 — 로그인한 회원이 열어도 온보딩으로 튕기지 않게)
- 모바일 375px 기준으로 먼저 만들고 PC는 가운데 최대 폭 480px. 상단은 어울림 로고만(메뉴 없음), 하단은 기존 `Footer`(사업자 정보 표시)

### 3-1. 결제 대기 화면

1. 제목 "어울림 결제 요청"
2. 카드: 결제명 / **금액(크게)** / 이용일 / 이용 시간·장소 / 결제 기한
3. 결제자 정보: 이름(필수, 미리 채움), 휴대폰 번호(필수, 01로 시작 10~11자리)
4. 환불 규정 표 — `app/lib/refund.ts` `REFUND_TABLE`과 같은 4단계·같은 색. 문구만 "파티" → "이용일"로 바꿔 표시
   - 이용일 5일 전 이상: 100% 환불 / 4일 전: 80% / 3일 전: 50% / 2일 전 ~ 당일: 환불 불가
   - 표 아래: "일수는 이용일 자정 기준으로 계산합니다. 취소 문의: info@thewoollim.com"
   - 관리자 추가 안내가 있으면 그 아래 표시(줄바꿈 유지)
   - 규정 비율을 새로 적어 넣지 말고 `refundTier`/`REFUND_TABLE`에서 가져와, 파티 규정이 바뀌면 함께 바뀌게 한다
5. 동의 (미리 체크 금지, 모두 체크해야 결제 버튼 활성)
   - [필수] 위 환불 규정을 확인했습니다
   - [필수] 결제자 정보(이름·휴대폰 번호) 수집·이용 동의 [보기]
6. 토스 결제위젯(결제수단 + 토스 약관 동의) — `customerKey`는 토스 SDK의 비회원 결제용 값(`ANONYMOUS`). 쓰는 SDK 버전 문서로 확인
7. [{금액}원 결제하기]

### 3-2. 그 밖의 상태 화면 (결제 버튼 없음)

| 상태 | 문구 |
|---|---|
| 결제 완료 | "결제가 완료되었습니다." + 결제명·금액·결제 일시 + [영수증 보기] |
| 취소됨 | "취소된 결제입니다." (부분 취소면 "{금액}원이 취소되었습니다.") |
| 기한 지남 | "결제 기한이 지난 링크입니다. 담당자에게 문의해주세요." |
| 중지 | "현재 결제할 수 없는 링크입니다. 담당자에게 문의해주세요." |
| 없는 링크 | "잘못된 결제 링크입니다." |

- 완료·취소 화면에서 결제자 이름·연락처는 다시 보여주지 않는다(링크가 다른 사람에게 전달될 수 있으므로)

## 4. 서버

새 폴더 `api/paylink/`. 토스 키는 기존 `api/payments/toss-config.php`를 읽기만 한다.

### 4-1. API

| API | 하는 일 |
|---|---|
| `GET view.php?t=` | 결제 페이지 표시용 정보. 결제 대기면 결제명·금액·이용일·이용 시간·장소·기한·추가 안내·환불 규정 4단계·미리 채울 이름. 그 밖에는 상태와 3-2에 필요한 값만 |
| `POST prepare.php` `{t, payerName, payerPhone, agreeRefund, agreePrivacy}` | 링크 상태 재확인(결제 대기·기한 안·중지 아님) → 주문번호 발급(10분 유효) → `{orderId, amount, orderName}` |
| `GET success.php` (토스 성공 이동) | 4-2 참고 |
| `GET fail.php` (토스 실패 이동) | 주문 정리 후 `/pay/?t=…&error=…`로 이동 |
| `api/admin/paylinks.php` | 관리자 세션 필수. 목록·상세·만들기·수정·중지/다시 열기·문자 발송·전액/부분 취소 |

- 금액은 **항상 서버에 저장된 링크 금액**을 쓴다. 화면에서 보낸 금액은 받지 않는다
- 같은 링크로 `prepare`를 너무 자주 부르지 못하게 제한(예: 같은 링크 10분에 10회)

### 4-2. 결제 승인 (`success.php`)

1. `orderId`로 링크를 찾고, 주문이 10분 안에 발급된 것인지 확인
2. 토스가 돌려준 `amount`가 링크 금액과 같은지 확인. 다르면 승인하지 않음
3. **링크 파일을 잠근 상태로** 이미 결제 완료인지 확인 → 아니면 토스 승인 API 호출
4. 승인 성공 → 결제 완료로 기록(paymentKey, 결제 수단, 승인 일시, 영수증 주소, 결제자 이름·연락처) → `/pay/?t=…&done=1`
5. 승인 뒤 저장이 실패하거나, 두 창에서 동시에 결제해 이미 완료된 링크였다면 → 기존 `success.php`의 자동 취소와 같은 방식으로 **그 결제를 즉시 전액 취소**하고 안내
6. 새로고침해도 다시 승인하지 않음(주문 정리)

### 4-3. 취소

- 기존 `api/admin/bookings.php`와 같은 토스 취소 API 호출(`cancelReason`, `cancelAmount`)
- 규정상 환불 금액은 `api/lib.php`의 기존 `refundQuote(결제액, 이용일)`로 계산한다(새 규칙을 따로 만들지 않음). 부분 취소가 있었으면 남은 결제액 기준
- `AGENTS.md` 6장 "환불 비율" 표에 결제 링크 파일(`api/admin/paylinks.php`, `/pay/` 화면)을 추가해, 규정이 바뀌면 함께 확인되게 한다
- 취소 이력(일시, 금액, 사유, 관리자) 저장. 누적 취소액이 결제액과 같아지면 "전액 취소", 아니면 "부분 취소"
- 이미 토스에서 취소된 건(`ALREADY_CANCELED`)은 성공으로 처리

### 4-4. 알림

- **운영자 텔레그램**(설정이 켜져 있을 때만, 기존 무음 시간 규칙 그대로)
  - 결제 완료: `[어울림] 대관료 결제 완료\n· {결제명}\n· {금액}원\n· 링크 #{번호}`
  - 취소: `[어울림] 결제 취소 · {금액}원\n· {결제명}\n· 처리: {관리자 아이디}` (무음)
  - **결제자 이름·연락처는 텔레그램에 넣지 않는다**
- **결제자 문자**(알리고, 결제 완료 시 1회): `[어울림] {결제명} {금액}원 결제가 완료되었습니다. 영수증: {영수증 주소}`
  - 발송 실패해도 결제 완료 처리에는 영향 없음

### 4-5. 저장

- `privateDataDir()/paylinks.json` (웹 루트 밖), 반드시 `withFileLock()`으로 읽고 쓰기
- 웹 루트 밖 폴더가 없으면 링크 만들기를 거절하고 관리자 화면에 사유 표시. 웹 루트 안(`api/data/`)으로 대체 저장 금지
- 기록 항목: 번호, 링크 코드, 결제명, 금액, 이용일, 이용 시간·장소, 추가 안내, 결제 당시 동의한 환불 규정 4단계(**결제 시점 값 그대로 보존**), 기한, 상태, 관리자 메모, 미리 채운 결제자 정보, 주문(orderId·발급 시각), 결제 정보, 취소 이력, 만든/고친 관리자, 일시
- 파티 예약·장바구니·쿠폰·파티 정원·매출 통계와 섞지 않는다

## 9. 구현 메모 (2026-11-03, 명세에 없던 세부를 정한 곳)

- **비회원 결제 값**: 토스 문서 사이트를 작업 환경에서 열 수 없어, 공식 SDK 패키지(`@tosspayments/tosspayments-sdk` 2.10.0)의 타입 정의로 확인했다 — 스크립트 태그 방식은 `TossPayments.ANONYMOUS`(값 `"@@ANONYMOUS"`). `requestPayment`의 `customerMobilePhone`은 숫자만 8~15자, `orderId`는 영문·숫자·`-_=` 6~64자, `orderName`은 100자 이내.
- **주문번호**: `pl<링크 번호>_<무작위 24자>`. 주문은 링크 안에 남겨 두고(결제 뒤에도), 결제 승인·중복 결제 취소 때 "이 링크가 발급한 주문인지"를 확인하는 데 쓴다.
- **중복 결제 자동 취소 안전장치**: 승인 주소의 `paymentKey`는 브라우저가 보낸 값이므로, 이미 결제된 링크에 결제가 또 들어오면 토스 결제 조회로 그 결제의 `orderId`가 이 링크가 발급한 주문인지 확인한 뒤에만 취소한다(다른 결제를 취소시키는 위조 요청 방지). 아직 승인 전(토스 상태가 DONE 아님)이면 취소할 것이 없으므로 안내만 한다.
- **승인 응답을 못 받은 경우**: 토스 연결 실패·5xx·`ALREADY_PROCESSED_PAYMENT`이면 토스 결제 조회로 실제 승인 여부를 확인해, 승인돼 있으면 그대로 결제 완료로 기록한다. 조회도 안 되면 결제 완료로 기록하지 않고 `_paylink_failure_alert.log`에 남긴 뒤 "카드 승인 문자를 받으셨다면 담당자에게 문의" 안내.
- **결제창을 연 사이 링크 중지**: 승인하지 않는다(중지가 우선). 기한은 주문 발급 시점에 확인하므로, 기한 직전에 결제창을 연 결제자는 10분 안에 결제를 마칠 수 있다.
- **이미 토스에서 취소된 결제(`ALREADY_CANCELED_PAYMENT`)**: 성공으로 처리하고, 관리자가 입력한 금액이 아니라 **남은 결제 금액 전부**를 취소로 기록한다(토스에서는 이미 전액 취소된 상태이므로 화면·통계를 실제와 맞춤). 이력에 "토스에서 이미 취소된 결제 (요청 금액 …원)"을 함께 남긴다.
- **[수정] 항목**: 명세의 항목에 더해 결제자 이름·연락처·관리자 메모도 결제 대기일 때 고칠 수 있다(연락처 오타를 고친 뒤 문자를 보낼 수 있게). 상태가 결제 대기이면 기한이 지난 링크도 수정해 기한을 늘릴 수 있다.
- **기본 결제 기한**: 7일 뒤 23:59. 이용일이 그보다 빠르면 이용일 23:59(기한이 이용일보다 늦을 수 없으므로).
- **이용일**: "오늘 이후"는 오늘 포함으로 구현했다(완료 기준의 "오늘 이전으로 저장할 수 없음"과 같게).
- **부분 취소 상태**: 저장 상태 `partial_cancelled`. 관리자 목록 필터에서는 [취소]에, 결제 페이지에서는 "{금액}원이 취소되었습니다." + 결제명·금액·결제 일시·영수증으로 보인다.
- **개인정보처리방침**: 명세대로 1항 수집 항목과 부칙 시행일만 바꿨다. 이용 목적·보유 기간은 결제 페이지의 수집·이용 동의 [보기]에 안내한다(방침 2·3항에 같은 내용을 넣을지는 법률 검토 때 함께 판단).
