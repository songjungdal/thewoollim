# 모집 자동 마감 · 수동 마감/해제 · 파티 취소 개발 명세서
- 작성일: 2026-11-21
- 기준 코드: main 30d0002

## 0. 목적과 결정 사항
당일 파티 직전에 신청·문의가 몰리는 것을 막는다.
- 자동 마감: 파티 시작 30분 전에 신청이 자동으로 마감된다
- 솔로파티 회차: 회차별 30분 전. 참가 항목은 포함된 회차 중 가장 이른 회차 시작 30분 전에 마감 (1부 19:00·2부 21:00 → "1부" "1부+2부"는 18:30, "2부만"은 20:30)
- 수동 마감: 관리자가 언제든 [모집 마감]으로 신청을 닫는다
- 마감 해제: 관리자가 [마감 해제]로 다시 연다. 30분 전 자동 마감도 풀 수 있다. 단, 시작 시각(회차 시작 시각)이 지나면 무조건 마감
- 파티 취소: 관리자가 [파티 취소]로 파티를 없애고 신청자 전원에게 전액 환불한다
- 정원: 마감 해제를 해도 정원(남은 자리) 규칙은 그대로다. 자리가 없으면 마감

## 1. 현재 구현 상태 (코드 확인 결과)
- 시간에 따른 마감은 화면에만 있다. app/lib/data.ts partyVisibility()가 행사 시작 시각이 지나면 "모집종료"로 보여준다. 30분 전 마감은 없다.
- 결제 서버(api/payments/pending.php, vbank-submit.php)는 파티 일시를 검사하지 않는다. 화면을 오래 열어 두거나 장바구니에 담아 두면 시작 뒤에도 결제가 될 수 있다.
- 정원 마감: 화면 partyStockStatus, 서버 partyRemainingSeats·partiesOverStock (참가확정 인원 기준, PR #124)
- partyEventDate()는 기기의 시간대로 계산한다(한국 밖 기기에서 시각이 어긋남). app/lib/partySeo.ts는 +09:00으로 계산한다.
- 관리자에 수동 마감·파티 취소 기능은 없다. 예약별 [취소]·[100%환불](api/admin/bookings.php cancel, cancel_full_refund)만 있다.
- 솔로파티 회차는 sessions[].startTime("19:00")이 있다.

## 2. 마감 판정 규칙 (화면·서버 공통)
### 2-1. 데이터 (parties.json, 파티 항목)
- recruitMode: "auto"(없으면 이것) | "closed"(관리자 마감) | "open"(관리자 마감 해제)
- recruitModeBy, recruitModeAt: 바꾼 관리자, 일시
- cancelledAt, cancelledBy, cancelReason: 파티 취소 정보 (있으면 취소된 파티)
- 기존 api/admin/parties.php 수정 저장 시 이 값들이 지워지지 않게 "요청에 없으면 유지" 목록에 추가 (139행 $keep 목록)

### 2-2. 시각 계산
- 모든 시각은 한국 시간(KST). 화면에서도 +09:00을 붙여 계산(partySeo.ts 방식). 기기 시간대에 따라 달라지면 안 된다.
- 파티 시작 = calendarDate + dateString의 HH:MM. 시각이 없으면 그날 23:59 (기존 규칙과 같음)
- 회차 시작 = calendarDate + 회차 startTime. 참가 항목 시작 = 포함 회차 중 가장 이른 회차 시작
- 마감 기준 시각 = 시작 − 30분. 상수 RECRUIT_CLOSE_BEFORE_MIN = 30 한 곳에 둔다

### 2-3. 판정 (위에서부터 먼저 맞는 것)
1. 취소된 파티 → 취소됨 (신청 불가)
2. 시작 시각이 지남 → 모집종료 (기존과 같음)
3. recruitMode = "closed" → 모집 마감 (관리자)
4. recruitMode = "open" → 모집 중 (30분 전 규칙 무시)
5. 마감 기준 시각(30분 전)이 지남 → 모집 마감 (자동)
6. 정원 마감 (partyStockStatus) → 기존과 같음
7. 그 밖 → 모집 중
- 참가 구성 솔로파티는 항목마다 2·4·5를 그 항목의 시작 시각으로 판정. 모든 항목이 마감이면 파티 전체가 마감
- 함수: 화면 app/lib/data.ts partyRecruitState(party, now) (항목별 결과 포함), 서버 api/lib.php partyRecruitState(array $party, int $now). 같은 규칙이므로 AGENTS.md 6장 표에 한 줄 추가

## 3. 화면
- 메인 파티 카드·일정·히어로(app/HomeClient.tsx, app/lib/hero.ts·api/_hero.php): 마감이면 "모집 마감" 배지와 "모집 마감 · 상세보기" 버튼 (지금 정원 마감과 같은 모양). 마감 임박 배지·D-day는 모집 중일 때만
- 파티 상세(PartyClientView.tsx, PartyCtaButtons.tsx)
  - 상태 배지·하단 버튼: 2-3 결과대로 "모집마감"/"모집 마감"
  - 참가 구성 파티의 항목 선택: 마감된 항목은 "마감"으로 비활성 (정원 마감 항목과 같은 모양)
  - 신청 버튼 위(또는 "신청 전 꼭 확인해주세요" 박스 첫 줄)에 고정 안내: "온라인 신청은 파티 시작 30분 전({HH:MM})에 자동 마감됩니다." 솔로 회차 파티는 "각 회차 시작 30분 전에 자동 마감됩니다."
  - 페이지를 열어 둔 채 마감 시각이 지나면 1분 안에 버튼이 마감으로 바뀐다(1분마다 다시 판정)
- 장바구니·결제 화면: 마감된 파티가 담겨 있으면 그 줄에 "모집 마감" 표시, 결제 버튼 비활성, "마감된 파티를 장바구니에서 빼주세요" 안내
- 취소된 파티: 메인·일정·히어로에서 숨김. 상세 주소로 들어오면 "주최측 사정으로 취소된 파티입니다" 표시, 신청 불가
- 마이페이지: 파티 취소로 취소된 예약은 "파티 취소 · 전액 환불" (무통장은 "파티 취소 · 환불 송금 예정"/"송금 완료")

## 4. 결제 서버 검사 (핵심)
- api/payments/pending.php, api/payments/vbank-submit.php: 담긴 파티(참가 구성은 고른 항목)마다 partyRecruitState 검사. 마감·종료·취소면 거절
  - 응답: 409, { ok:false, code:"RECRUIT_CLOSED", error:"모집이 마감된 파티가 있습니다: {파티 제목}" }
  - 화면은 이 응답을 받으면 안내창을 띄우고 장바구니를 새로 읽는다
- api/payments/success.php: 검사하지 않는다. 마감 전에 발급된 주문(10분 유효)은 결제가 끝나면 그대로 접수(결제창을 연 사람이 승인 직후 취소되는 일을 막기 위해)
- 관리자가 직접 만드는 예약은 검사하지 않는다

## 5. 관리자: [모집 마감] / [마감 해제]
- 위치: 관리자 [매칭파티] 탭(파티 관리)의 파티 줄과 파티 수정 화면 상단
- 파티 줄에 모집 상태 칩: "모집 중 · {MM/DD HH:MM} 자동 마감" / "모집 마감(자동)" / "모집 마감(관리자)" / "마감 해제됨 · 시작까지 신청 가능" / "모집종료" / "취소됨". 솔로 회차 파티는 회차별 자동 마감 시각을 펼쳐 보기
- 버튼
  - 모집 중일 때: [모집 마감] → 확인창 "지금부터 신청을 받지 않습니다." → recruitMode="closed"
  - 마감(자동·관리자)일 때: [마감 해제] → 확인창 "파티 시작 시각({HH:MM})까지 다시 신청을 받습니다. 정원이 남아 있어야 신청할 수 있어요." → recruitMode="open"
  - 마감 해제 상태에서: [다시 자동 마감으로] → recruitMode="auto"
  - 시작 시각이 지났거나 취소된 파티는 버튼 없음
- API: api/admin/parties.php에 action: "recruit" { partyId, mode: "auto"|"closed"|"open" } 추가 (관리자 세션 필수, withFileLock)
- 모든 변경을 관리자 활동 로그에 남긴다

## 6. 관리자: [파티 취소] (전원 전액 환불)
### 6-1. 버튼·확인
- 위치: 파티 수정 화면 하단 (기존 [삭제]와 떨어진 곳, 빨간 외곽선 버튼). 시작 전·후 모두 가능, 이미 취소된 파티는 없음
- 누르면 미리보기 창:
  - 카드·간편결제 N건 · 합계 {금액}원 → 토스에서 자동 전액 취소
  - 무통장 입금 완료 N건 · 합계 {금액}원 → 관리자가 직접 송금 (자동 환불 안 됨)
  - 무통장 입금 대기 N건 → 예약만 취소 (돈을 받지 않았으므로 환불 없음)
  - 취소요청 진행 중 N건 → 전액 환불로 처리 (위 결제 수단별 방식)
  - 이미 취소·환불완료된 예약은 대상 아님
  - 취소 사유 입력(필수, 50자, 문자에 들어감. 기본값 "주최측 사정")
  - [신청자에게 문자 보내기] 체크 (기본 켬)
  - "되돌릴 수 없습니다" 경고 + 파티 제목을 그대로 입력해야 [파티 취소 실행] 활성
- 미리보기 숫자는 서버가 계산해서 준다(action: "cancel_preview")

### 6-2. 처리 (api/admin/parties.php action: "cancel_party")
1. 파티에 cancelledAt 등을 먼저 기록 → 이 순간부터 신청·결제 불가 (4장)
2. 대상 예약을 하나씩 처리. 각 예약은 기존 api/admin/bookings.php의 처리와 같은 코드를 쓴다(공통 함수로 빼서 재사용, 복사 금지)
   - 카드: 남은 결제 금액 전액 토스 취소 (cancel_full_refund와 같음) → cancelled
   - 무통장 입금 완료: cancelled + manualRefund: { amount, status: "pending" }
   - 무통장 입금 대기: cancelled (환불 없음)
   - 인원 차감·쿠폰 사용 되돌리기(releaseCouponUsage)·참가 구성 회차 인원은 기존 취소와 같게
   - 예약에 cancelReason: "party_cancelled" 기록
3. 예약 하나가 실패해도(토스 오류 등) 나머지는 계속 처리. 결과 화면에 성공/실패 목록
4. 다시 실행 가능: 취소된 파티에서는 [남은 환불 다시 시도]로 실패한 예약만 다시 처리. 이미 처리된 예약은 건너뜀. 토스 ALREADY_CANCELED는 성공으로 봄
5. 문자(알리고): 처리된 예약마다 1회, 기존 문자 제외 규칙(isSmsExcludedAccount) 적용
   - 카드: "[어울림] 파티 취소 안내\n{MM/DD} {파티 제목}이(가) {사유}로 취소되었습니다. 결제하신 {금액}원은 전액 취소되며, 카드사에 따라 환불 반영까지 시간이 걸릴 수 있습니다. 불편을 드려 죄송합니다."
   - 무통장 입금 완료: "... 입금하신 {금액}원은 전액 환불해 드립니다. 환불받으실 계좌를 이 번호로 문자 주시면 송금해 드리겠습니다."
   - 무통장 입금 대기: "... 아직 입금 전이시라면 입금하지 않으셔도 됩니다."
   - 개발 중에는 실제 발송 금지(흉내 서버로 확인)
6. 텔레그램(설정 켜져 있을 때): "[어울림] 파티 취소 · {파티 제목}\n· 카드 환불 N건 / 무통장 송금 필요 N건 / 실패 N건\n· 처리: {관리자 아이디}" — 회원 이름·연락처 넣지 않음
7. 관리자 활동 로그에 남김

### 6-3. 무통장 송금 관리
- 취소된 파티 화면에 "무통장 환불 송금" 목록: 이름, 연락처, 금액, 상태(송금 필요/송금 완료)
- [송금 완료] 버튼 → manualRefund.status="done", 완료 일시·관리자 기록 (실제 송금은 관리자가 은행에서 직접)

### 6-4. 하지 않는 것
- 파티 취소를 되돌리는 기능은 만들지 않는다(환불이 이미 나가므로)
- 예약 상태값을 새로 만들지 않는다(기존 cancelled 사용)
- 매칭 투표·후기 데이터는 건드리지 않는다

## 7. 유지할 기능 (회귀 금지)

- 회원 취소 요청·관리자 [취소]·[100%환불]·[환불 승인]·환불 규정
