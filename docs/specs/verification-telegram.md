# 심사 대기 텔레그램 알림 개발 명세서

- 작성일: 2026-11-02
- 기준 코드: `songjungdal/thewoollim` main `f74b7fb` (PR #116 사진 심사·직업 인증 병합 이후)
- 관련 명세: `docs/specs/photo-job-verification.md`

---

## 0. 목적

회원이 사진 심사나 직업 인증을 요청하면 운영자들이 함께 있는 **텔레그램 그룹방에 봇이 바로 알려준다.** 관리자 화면을 계속 열어 두지 않아도 심사 대기를 빨리 처리할 수 있게 하는 것이 목적이다.

| 항목 | 결정 |
|---|---|
| 받는 곳 | 운영자 텔레그램 그룹방 1곳 (봇이 그룹에 메시지 발송) |
| 보내는 때 | 심사 요청이 들어올 때마다 즉시 + 처리(승인·반려)되면 처리 완료 알림 + 매일 오전 10시 남은 대기 요약 |
| 밤 시간 | 22:00~08:00 사이 메시지는 **무음**으로 보낸다(알림은 오되 소리 없음) |
| 개인정보 | **이름·연락처·이메일·사진·서류는 보내지 않는다.** 성별·나이대·구분만 보낸다 |
| 비용 | 없음 (텔레그램 봇 API는 무료) |

---

## 1. 현재 상태 (코드 확인)

- 운영자에게 오는 실시간 알림은 없다. 관리자 대시보드 첫 팝업 "확인할 업무"에 `인증 심사 대기 N건`만 표시된다(`app/admin****/dashboard/page.tsx`, `api/admin/verifications.php` `_verifyPendingCount`)
- 심사 요청 접수: `api/verification/photo.php`, `api/verification/job.php`
- 승인·반려 처리: `api/admin/verifications.php`
- 자동 작업: 서버 타이머로 `api/cron/profile_24h_reminder.php`가 **매시 정각** 실행됨(`docs/PROJECT_OVERVIEW.md` 기준)
- 회원 문자(알리고)는 `api/admin/_verification_sms.php`에서 결과 안내만 보냄. 이번 작업과 별개로 그대로 둔다

## 2. 텔레그램 연결 (대표님이 한 번만 하는 준비)

화면 안내문(관리자 설정 영역에 그대로 표시)에도 이 순서를 넣는다.

1. 텔레그램에서 **@BotFather** 검색 → `/newbot` → 봇 이름 입력 → 받은 **봇 토큰**을 복사
2. 운영자 그룹방을 만들고(또는 기존 방) 방금 만든 봇을 **초대**
3. 그룹방에서 `/start` 를 한 번 입력
4. 관리자 대시보드 > 인증 심사 탭 > "텔레그램 알림 설정"에 토큰을 붙여넣고 **[그룹 찾기]** → 목록에서 그룹 선택 → **[저장]** → **[테스트 알림 보내기]**

---

## 3. 관리자 화면: "텔레그램 알림 설정"

- 위치: 관리자 "인증 심사" 탭 상단, [사진 심사 필수] 스위치 아래 접기/펼치기 카드
- 항목
  - 알림 켜기/끄기 스위치 (기본 꺼짐)
  - 봇 토큰 입력칸: 저장 후에는 **앞 4자리만 보이고 나머지는 가림**(`1234••••••`). 다시 화면에 원문을 내려주지 않는다. [토큰 바꾸기]로만 새로 입력
  - [그룹 찾기]: 서버가 텔레그램 `getUpdates`를 호출해 봇이 들어가 있는 그룹(그룹·슈퍼그룹)의 이름과 번호를 목록으로 보여줌. 못 찾으면 "그룹방에 봇을 초대한 뒤 /start 를 입력하고 다시 눌러주세요" 안내
  - 연결된 그룹 이름 표시
  - 관리자 화면 바로가기 주소(선택): 입력하면 알림 끝에 링크를 붙임. 비워두면 "관리자 > 인증 심사에서 확인" 문구만
  - [테스트 알림 보내기]: "[어울림] 텔레그램 알림 연결 테스트입니다." 발송 후 성공/실패 표시
- 설정 변경은 기존 관리자 활동 로그에 남긴다(토큰 원문은 로그에 남기지 않음)

## 4. 보내는 메시지

모든 메시지는 일반 텍스트(서식 없음), 링크 미리보기 끔.

### 4-1. 심사 요청 접수 (즉시)

```
[어울림] 사진 심사 요청
· 남성 · 30대 초반
· 첫 제출
· 접수 11/02(월) 17:30
· 현재 대기 3건
관리자 > 인증 심사에서 확인
```

- 첫 줄: `사진 심사 요청` / `직업 인증 요청 (직장인|사업자|기타)`
- 셋째 줄(사진만): `첫 제출` / `재제출(반려 후)` / `사진 교체(승인 회원)`
- 나이대는 참여자 명단과 같은 기존 함수(`ageBand`)로 만든다
- 사업자라면 국세청 확인 결과를 한 줄 추가: `· 국세청 확인: 일치 | 불일치 | 확인 불가`
- 관리자 주소가 설정돼 있으면 마지막 줄을 그 링크로 바꿈

### 4-2. 처리 완료 (운영자끼리 중복 처리 방지용, 항상 무음)

```
[어울림] 처리 완료 · 사진 승인
· 남성 · 30대 초반 (17:30 접수)
· 처리: {관리자 아이디}
· 남은 대기 2건
```

- 반려면 `사진 반려 (사유: 얼굴이 잘 보이지 않음)` 처럼 사유 포함
- 관리자 아이디 외에 처리자 개인정보는 넣지 않는다

### 4-3. 매일 오전 10시 대기 요약 (대기 1건 이상일 때만)

```
[어울림] 심사 대기 요약
· 사진 3건 / 직업 1건
· 가장 오래된 요청: 14시간 전
관리자 > 인증 심사에서 확인
```

- 기존 매시 정각 자동 작업(`api/cron/profile_24h_reminder.php`)에 붙여 **KST 10시에만** 실행. 같은 날 두 번 보내지 않도록 마지막 발송 날짜를 저장
- 새 서버 타이머는 만들지 않는다

### 4-4. 보내지 않는 경우

- 알림 스위치가 꺼져 있거나 토큰·그룹이 설정되지 않음
- **테스트 회원(`isTestUser`)의 요청과 처리** (명단 소음 방지. 연결 확인은 [테스트 알림 보내기]로)

## 5. 서버

- 새 파일 `api/notify/_telegram.php`
  - `telegramSend(string $text, bool $silent): bool` — `POST https://api.telegram.org/bot<토큰>/sendMessage`, 본문 `chat_id`, `text`, `disable_notification`, `link_preview_options: {"is_disabled": true}`
  - 22:00~08:00(KST)이면 `$silent = true`로 강제
  - **연결 3초·전체 5초 제한.** 실패해도 예외를 밖으로 던지지 않고 `false`만 돌려준다. 재시도 반복 금지
  - 실패 기록은 `dataDir()` 로그에 시각·HTTP 코드·텔레그램 오류 설명만 남김. **토큰이 들어간 주소는 절대 로그에 남기지 않는다**
- 설정 저장: `privateDataDir()/notify/telegram.json` (웹 루트 밖, 파일 권한 0600, `withFileLock`). 웹 루트 밖 폴더가 없으면 설정 저장을 거절하고 화면에 사유 표시
- 관리자 API `api/admin/notify-telegram.php` (관리자 세션 필수)
  - `GET` 설정 보기(토큰은 가린 값만), `POST action=save|find_groups|test|toggle`
  - `find_groups`: `getUpdates` 결과에서 `chat.type`이 `group`/`supergroup`인 것만 이름·번호로 중복 없이 반환
- 호출 위치
  - `api/verification/photo.php`, `api/verification/job.php`: 접수 저장이 **끝난 뒤** 호출 (알림 실패가 접수 결과에 영향 없음)
  - `api/admin/verifications.php`: 승인·반려 저장이 끝난 뒤 호출
  - 가능하면 회원 응답을 먼저 보낸 뒤 발송(`fastcgi_finish_request`가 있으면 사용). 없으면 5초 제한 안에서 그대로 발송
- 개인정보처리방침은 바꾸지 않는다(텔레그램으로 이름·연락처 등 개인을 알아볼 수 있는 정보를 보내지 않으므로). 이 원칙을 코드 주석에 적어 이후 메시지에 개인정보가 추가되지 않게 한다

## 6. 유지할 기능 (회귀 금지)

- 사진 심사·직업 인증 접수, 승인·반려, 결과 문자(알리고), 결제 전 검사, [사진 심사 필수] 스위치
- 기존 자동 작업(프로필 재안내 문자)의 발송 대상·시각·중복 방지
- 회원가입·결제·예약·환불 흐름 전체
- 텔레그램이 응답하지 않거나 막혀도 위 기능이 모두 정상 동작해야 함

## 7. 테스트 및 완료 기준

로컬 검증은 텔레그램 대신 흉내 서버(가짜 응답)로 한다. 실제 텔레그램 발송은 배포 후 대표님이 [테스트 알림 보내기]로 확인.

- [ ] 설정 저장 후 화면·API 응답 어디에도 토큰 원문이 나오지 않음
- [ ] [그룹 찾기]가 그룹·슈퍼그룹만 보여주고, 못 찾으면 안내 문구가 나옴
- [ ] 사진 첫 제출 / 재제출 / 교체, 직업(직장인·사업자·기타) 요청마다 4-1 형식 메시지 1건
- [ ] 승인·반려 시 4-2 메시지 1건(무음)
- [ ] 22:00~08:00 메시지는 `disable_notification=true`
- [ ] 10시 요약: 대기 있을 때 하루 1번만, 대기 0건이면 안 보냄, 매시 실행돼도 중복 없음
- [ ] 테스트 회원 요청·처리는 알림 없음
- [ ] 스위치 꺼짐·설정 없음이면 아무것도 보내지 않음
- [ ] 텔레그램 쪽 실패(타임아웃·401·400) 때도 회원 접수와 관리자 승인은 정상 완료, 로그에 토큰 없음
- [ ] 메시지에 이름·연락처·이메일·사진이 들어가지 않음
- [ ] 관리자 설정 카드가 375px·1280px에서 깨지지 않음
- [ ] `php -l`, `npx tsc --noEmit`, `npx eslint .`, `npm run build` 통과

## 8. 확인 필요

1. 운영 서버에서 `api.telegram.org`로 나가는 연결이 막혀 있지 않은지 — 배포 후 [테스트 알림 보내기]로 확인. 실패하면 서버 보안그룹·방화벽 확인 필요(서버 설정 변경은 대표님 허락 후)
2. 서버 PHP의 `curl` 사용 가능 여부 (알리고 문자 발송이 curl을 쓰고 있어 가능할 것으로 보이나 코드로 확인)
