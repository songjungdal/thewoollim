## 구현 메모 (원문을 코드에 옮기며 정한 것)

### 1. 메인 '파티 신청' (`app/HomeClient.tsx` #apply)

- 탭과 파티 종류
  - "로테이션 소개팅" = 종류 `matching`(종류 값이 없는 예전 파티 포함, `partyTypeOf`)
  - "파티" = 종류 `solo`
  - 대상·테마·지역으로 거르지 않는다. 요약 줄·[초기화]도 없어진다.
- "날짜 빠른 순"은 지금의 노출 규칙 안에서 적용한다.
  - 모집 중(행사 전) 파티가 날짜 빠른 순으로 먼저 나온다.
  - 이미 끝난 파티("모집종료" 카드, 끝난 지 21일 이내)는 그 뒤에 날짜 빠른 순으로 나온다.
  - 끝난 지 21일이 지난 파티는 지금처럼 목록에서 빠진다. 더보기(PC 12개 / 모바일 10개)도 그대로이고, 탭을 바꾸면 더보기는 다시 접힌다.
- 주소 연동은 유지한다. `/?type=solo#apply`로 들어오면 "파티" 탭이 선택된 채 열린다. 탭을 바꾸면 주소의 `?type=`만 바뀐다("로테이션 소개팅"은 `?type=` 없음). 파티 상세에서 뒤로 돌아오면 보던 탭과 더보기 상태를 되살린다. 예전 화면에서 저장된 값이 "전체"이면 "로테이션 소개팅"으로 연다.
- 탭에 파티가 하나도 없을 때 문구: "지금 신청할 수 있는 일정이 없습니다." / "새 일정이 열리면 이곳에 안내해 드릴게요."
- 카드 배지
  - 좌측 상단: 대상 배지. 파티의 혼인여부(`allowedMaritalStatus`) 값으로 정한다. 값이 없거나 `all`이면 "누구나". 모집 중·마감·종료 카드 모두에 붙는다.
  - 우측 상단: 대상 배지(싱글·돌싱)를 없앤다. 모집 중일 때 D-day가 남는다.
  - 정원이 다 찬 카드의 "모집 마감", 행사가 끝난 카드의 "모집종료"는 대상 배지가 아닌 상태 표시라 지금처럼 둔다.
- "파티 일정" 섹션(달력·리스트·패널)은 이번 범위가 아니라 그대로 둔다(종류 배지와 대상·테마·지역 태그 유지).

### 2. 관리자 파티수정 (`app/admin****/dashboard/page.tsx`)

- 혼인여부: 표시 순서와 문구만 바꾼다. 저장값(`싱글` / `돌싱` / `all`)과 새 파티 기본값(누구나 = `all`)은 그대로.
- 대상별: 첫 선택지 "미지정"을 "누구나"로 문구만 바꾼다. 저장값은 지금처럼 빈 값이다("누구나"라는 새 값을 저장하지 않는다). 순서는 누구나 / 싱글 / 돌싱.
- 테마별: 선택지는 미지정 / 로테이션소개팅 / 와인파티 / 솔로파티. 저장값은 화면 문구와 같다(`로테이션소개팅`, `와인파티`, `솔로파티`). "미지정"(빈 값)은 지역별과 같은 방식으로 남겨 둔다.
  - 예전 값(티타임·사케파티·쿠킹클래스)은 새로 고를 수 없다.
  - 예전 값이 저장된 파티를 열면 선택지 맨 아래에 "티타임 (이전 분류)"처럼 그 값 하나가 더 보이고 선택된 채로 열린다. 그대로 저장하면 값이 유지되고, 다른 값을 고르면 바뀐다.
  - 서버(`api/admin/parties.php`)는 새 값 3개와 예전 값 3개를 모두 받는다. 예전 값 파티를 다른 항목만 고쳐 저장해도 테마가 지워지지 않게 하기 위해서다.
  - 화면(`app/lib/partyNormalize.ts`)도 예전 값을 지우지 않고 읽는다. "파티 일정" 섹션은 예전 값을 지금처럼 보여 준다("쿠킹클래스"는 "세션").
- 지역별: 그대로.

### B. 혼인여부 문구와 실제 신청 제한

- 신청 제한 코드: `app/lib/eligibility.ts` `checkEligibility`. 화면에서만 검사하고 서버 검사는 없다.
- 동작: 혼인여부가 "싱글" **이거나 대상별이 "싱글"**이면 돌싱 회원을 막는다. 그 밖에는 아무도 막지 않는다.
- 문구와 같은 것: 싱글 전용 → 돌싱 차단, 돌싱 → 싱글도 신청 가능, 누구나 → 모두 신청 가능. 요청의 예시("돌싱" 선택 시 싱글 신청 불가)는 일어나지 않는다.
- **문구와 다른 것**: 혼인여부를 "돌싱 (싱글도 허용)"이나 "누구나 (모두 허용)"로 두어도 **대상별을 "싱글"로 두면 돌싱 회원이 신청할 수 없다.** 요청대로 고치지 않고 보고한다.
  - 지금 운영 파티 27건에는 이 조합이 없다(혼인여부와 대상별이 같은 값이거나, 혼인여부 누구나 + 대상 미지정).
  - 이번 변경으로 카드 배지는 혼인여부를 따르므로, 이 조합으로 저장한 파티는 카드에 "돌싱"이나 "누구나"가 보이는데 돌싱 회원은 막히게 된다.

### C. 후속 결정 — 신청 제한은 혼인여부만 따른다 (2026-10-25 사용자 요청)

사용자 요청 원문: "신청 제한이 혼인여부 설정만 따르도록 고쳐줘. 대상별이 '싱글'이어도 혼인여부가 돌싱/누구나면 돌싱 회원이 신청할 수 있게."

- `app/lib/eligibility.ts` `checkEligibility`: 돌싱 회원 차단은 혼인여부가 "싱글"(싱글 전용)일 때만. 대상별(`targetGroup`)은 신청 제한에 쓰지 않는다. 쓰이지 않는 요약 함수 `eligibilitySummary`도 같은 기준으로 맞췄다.
- 함께 바꾼 것: 파티 상세 필수 확인 사항 맨 끝의 "싱글 전용 파티 안내 (SINGLES ONLY)" 경고(`app/party/[id]/PartyClientView.tsx` `targetVariant`)도 혼인여부가 "싱글"일 때만 보인다. 예전처럼 대상별 "싱글"만으로 띄우면 돌싱 회원이 신청할 수 있는 파티에 "싱글이 아니면 회원탈퇴·블랙리스트" 경고가 붙기 때문이다.
  - 혼인여부 "돌싱" + 대상별 "싱글" → "OPEN MATCHING" 안내(싱글·돌싱 모두 참가 가능)
  - 혼인여부 "누구나" + 대상별 "싱글" → 대상별 안내 없음
  - 그 밖의 조합은 예전과 같다.
- 지금 운영 파티 27건에는 대상별 "싱글"이면서 혼인여부가 "싱글"이 아닌 파티가 없어, 지금 화면에서 달라지는 파티는 없다.

### D. 후속 요청 — 관리자 파티수정 창의 파티 종류 이름 (2026-10-25 사용자 요청)

사용자 요청 원문: "관리자페이지 파티관리의 파티수정 부분에서 파티 종류도 로테이션소개팅 / 파티 로 명칭을 수정해줘."

- 파티 등록·수정 창의 "파티 종류" 버튼: [매칭파티] [솔로파티] → [로테이션소개팅] [파티]. 저장값(`matching` / `solo`)과 동작은 그대로.
- 같은 창 안에서 종류 이름이 나오는 문구도 같은 이름으로 맞췄다(`app/lib/data.ts` `PARTY_TYPE_ADMIN_LABELS`).
  - [파티]를 고르면 나오는 안내: "‘파티’는 매칭 투표가 없습니다."
  - 종류를 바꿀 때 확인창: "상세페이지 안내를 로테이션소개팅(파티) 기본 내용으로 바꿀까요?"
  - 참가 구성에 신청자가 있어 종류를 바꿀 수 없을 때 알림: "… 로테이션소개팅으로 바꿀 수 없습니다."
  - [상세페이지 안내] 탭: [기본 내용으로 되돌리기 (…)] 버튼과 되돌리기 확인창, [다른 파티에서 불러오기] 목록의 종류 이름.
- 바꾸지 않은 것: 관리자 파티 목록의 종류 필터·배지, 예약 현황의 종류 배지, 회원이 보는 화면(파티 상세·문자·법적 문서 등)의 "매칭파티" / "솔로파티".
