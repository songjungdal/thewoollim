## 1. 작업 목적

솔로파티는 한 파티 안에 **1부·2부 같은 회차**가 있고, 회원은 **1부만 / 2부만 / 1부+2부** 같은 **참가 항목**을 골라 결제한다. 참가비는 항목별·성별로 다르다. 이를 관리자가 파티마다 자유롭게 구성하고, 신청·결제·정원·예약·문자가 항목에 맞게 동작하도록 만든다.

**매칭파티는 이번 작업에서 아무것도 바뀌지 않는다.**

## 2. 운영 방식 (대표 확정, 2026-10-09)

| 항목 | 내용 |
|---|---|
| 참가 항목 구성 | **파티마다 자유롭게** 구성한다. 예: 1부만 열기, 1·2·3부, 1부+2부만 판매 |
| 묶음 가격 | 1부+2부 같은 묶음 항목도 **가격을 직접 입력**한다(자동 합산 아님) |
| 가격 단위 | 항목마다 **남성가·여성가**를 따로 둔다 |
| 정원 | **회차별로 따로** 센다. 1부+2부 신청자는 1부·2부 정원을 **모두** 차지한다 |
| 대상 | 솔로파티만. 매칭파티는 지금 구조를 그대로 쓴다 |

## 4. 용어

- **회차(session):** 실제 진행 단위. 예: 1부(19:00), 2부(21:30). 회차마다 시작 시각과 남/여 정원이 있다.
- **참가 항목(option):** 회원이 고르고 결제하는 상품. 예: "1부", "2부", "1부+2부". 항목은 하나 이상의 회차를 포함하고, 남/여 가격이 있다.

## 5. 데이터 설계

### 5-1. 파티에 추가하는 필드 (솔로파티만)

```ts
sessions?: {
  id: string;          // "s1", "s2" … 서버가 만들고 바꾸지 않는다
  name: string;        // "1부" (20자 이하)
  startTime: string;   // "19:00" (HH:MM)
  maleStock: number;   // 1~100
  femaleStock: number; // 1~100
}[];                   // 1~5개

options?: {
  id: string;          // "o1", "o2" … 서버가 만들고 바꾸지 않는다
  name: string;        // "1부+2부" (20자 이하)
  sessionIds: string[];// 포함 회차, 1개 이상, 위 sessions 의 id 만
  priceMale: number;   // 1원 이상
  priceFemale: number; // 1원 이상
}[];                   // 1~6개
```

- **`options`가 없는 파티는 지금과 똑같이 동작한다.** 기존 매칭파티와 이미 등록된 솔로파티가 모두 해당하며, 데이터 변환은 하지 않는다.
- 솔로파티에 `options`를 넣으면, 그 파티의 기존 `priceMale`/`priceFemale`/`maleStock`/`femaleStock`은 **화면 표시나 폴백용으로만** 남긴다. 저장할 때 다음 값으로 맞춘다.
  - `price*`: 항목 가격 중 최솟값
  - `*Stock`: 회차 정원 중 최댓값
- 파티의 `dateString`/`calendarDate`는 **첫 회차 시작 시각** 기준으로 맞춘다. 정렬, 달력, 모집 종료 판단이 이 값을 계속 쓰기 때문이다.
- id는 서버가 만든다. 이름은 바꿀 수 있다.

### 5-2. 인원 집계

- `party_counts.json`의 파티 항목에 회차별 집계를 추가한다.
  `{ "61": { "male": 12, "female": 10, "sessions": { "s1": {"male": 9, "female": 8}, "s2": {"male": 7, "female": 6} } } }`
- `male`/`female`은 계속 **그 파티에 신청한 사람 수**다. 1부+2부 신청자도 1명으로 센다. 기존 화면과 관리자 집계가 이 값을 그대로 쓸 수 있다.
- `sessions`는 **회차별 참석 인원**이다. 1부+2부 신청자는 s1과 s2에 각각 +1 한다.
- 늘리고 줄이는 작업은 지금처럼 파일 잠금(flock) 안에서 한 번에 처리한다.

### 5-3. 예약에 추가하는 필드 (결제 시점 사본)

- `optionId`
- `optionName`
- `sessionIds`
- `sessionTimes` (예: `["19:00", "21:30"]`)

나중에 관리자가 항목 이름이나 회차를 바꿔도, 이미 결제된 예약은 결제 당시 내용으로 남는다.

**단, 시각은 예외다.** 회차 시작 시각은 신청자가 있어도 바꿀 수 있다. 그래서 다음 세 가지는 **파티의 현재 회차 시각**을 쓴다. 예약의 `sessionIds`로 회차를 찾고, 찾지 못할 때만 `sessionTimes` 사본을 쓴다.
- 문자 발송 시점(2시간 전 안내)
- 문자 속 시각(신청 접수·참가확정·전날·2시간 전·취소)
- 마이페이지에 보이는 시각

매칭파티가 `dateString`을 고치면 문자에 바로 반영되는 것과 같은 규칙이다. 사본 시각을 그대로 쓰면, 2부 시각을 21:30에서 21:00으로 바꿨을 때 2부 신청자의 2시간 전 문자가 아예 나가지 않는다.

### 5-4. 장바구니 항목

- 형태: `{ partyId, optionId?, quantity }`
- 같은 파티에서 다른 항목을 다시 담으면 **기존 항목을 바꾼다**(파티당 하나).

## 6. 서버 변경

| `api/payments/vbank-submit.php` | 사전 검사를 회차 기준으로 하고, 예약에 5-3 필드를 저장한다. |

### 6-1. 저장 검사 규칙 (`sanitizePartyOptions`)

- 대상: 솔로파티만. 매칭파티에 `sessions`·`options`가 오면 무시한다.
- 회차 1~5개, 항목 1~6개
- 이름 20자 이하. 회차 이름끼리, 항목 이름끼리 겹치면 안 된다.
- `startTime`은 `HH:MM` 형식. 회차는 시작 시각 순서로 정렬해 저장한다.
- 항목은 실제 있는 회차를 1개 이상 포함해야 하고, 남/여 가격은 1원 이상이다.
- **신청자가 있을 때 막는 수정**
  - 신청자가 있는 회차나 항목은 **삭제할 수 없다**.
  - 신청자가 있는 항목의 **포함 회차는 바꿀 수 없다**. 이름과 가격은 바꿀 수 있고, 가격 변경은 이후 결제부터 적용된다.
  - 회차 정원을 **현재 신청 인원보다 적게** 바꿀 수 없다.
  - 신청자는 **취소되지 않은 예약** 기준으로 센다.

### 6-2. 안내 문자

| 문자 | 변경 |
|---|---|
| 신청 접수(`_pending_sms.php`) | 제목 줄 아래에 항목 이름을 추가한다. 예: "참가: 1부+2부" |
| 참가확정(`_confirm_sms.php`) | 항목 이름과 **처음 참석하는 회차의 시작 시각**을 추가한다 |
| 전날 안내(`d1_reminder.php`) | 항목 이름과 처음 참석하는 회차의 시작 시각을 넣는다 |
| 2시간 전 안내(`start2h_reminder.php`) | **예약마다** 처음 참석하는 회차의 시작 시각 기준으로 보낸다. 2부만 신청한 회원은 2부 시작 2시간 전에 받는다. 같은 회원이 중복으로 받지 않게 한다. |

- 테스트 계정·관리자 계정 제외 규칙은 그대로 둔다.

## 7. 관리자 화면

### 7-1. 파티 등록·수정 ([기본 정보] 탭, 솔로파티를 골랐을 때만)

지금의 "남/여 참가비"와 "남/여 정원" 입력 자리에 **"참가 구성"** 영역을 보여준다.

1. **[기본 구성 넣기] 버튼:** 아래 구성을 한 번에 채운다. 가격과 정원은 비워 두어 직접 입력하게 한다.
   - 회차: "1부", "2부"
   - 항목: "1부", "2부", "1부+2부"
2. **회차 목록:** 줄마다 [이름, 시작 시각, 남 정원, 여 정원, 삭제]가 있고, 아래에 [+ 회차 추가] 버튼을 둔다.
3. **참가 항목 목록:** 줄마다 [이름, 포함 회차(체크박스), 남 가격, 여 가격, 위로/아래로, 삭제]가 있고, 아래에 [+ 항목 추가] 버튼을 둔다.
4. **안내 문구:** "1부+2부처럼 여러 회차를 포함한 항목을 신청하면, 포함된 회차의 정원을 모두 차지합니다."
5. **신청자가 있는 회차·항목:** 삭제 버튼을 끄고 "신청자 N명"을 표시한다.

- 저장할 때 화면에서도 6-1 규칙을 먼저 검사하고, 빠진 항목은 기존 누락 알림에 함께 보여준다.
- [참가 구성 사용]일 때는 기존 "모집 인원(남/여)" 누락 검사를 하지 않는다.
- 저장하면 "일시" 칸의 시각이 첫 회차 시각으로 자동으로 바뀐다. 일시 칸 아래에 "시각은 첫 회차 시각으로 자동 저장됩니다"를 보여준다. "오후 7:00"처럼 쓰면 "오후 19:00"이 되므로, 시각은 24시간 형식(19:00)으로 쓰도록 placeholder로 안내한다.
- 매칭파티 화면과 참가 구성을 넣지 않은 솔로파티는 지금 입력칸(남/여 참가비·정원)을 그대로 쓴다. 솔로파티는 둘 중 하나를 고른다.
  - [참가 구성 사용]
  - [단일 가격]

### 7-2. 목록·예약 현황

- 파티 목록의 참가비 칸: 항목이 있으면 "항목 3개 · ₩30,000~"처럼 표시한다.
- 파티 목록의 정원 칸: 항목이 있으면 회차별로 표시한다(예: "1부 20/20명 · 2부 15/15명"). 대표 정원(회차 정원 최댓값)만 보이면 실제 정원으로 오해할 수 있다.
- 예약/신청 현황
  - 신청자 줄마다 **항목 이름** 열을 둔다.
  - 파티별 묶음 제목 아래에 **회차별 남/여 인원/정원**을 표시한다(예: "1부 남 9/20 · 여 8/20 | 2부 남 7/15 · 여 6/15").
- 운영 현황 팝업: 파티 단위 숫자는 그대로 둔다.

## 8. 사용자 화면

### 8-1. 파티 상세 (`PartyClientView.tsx`, 항목이 있는 솔로파티)

**상단 정보**
- "일시" 줄: 날짜와 회차 시간표를 함께 보여준다(예: "1부 19:00 · 2부 21:30").
- "참가비" 줄: 항목별 남/여 가격을 목록으로 보여준다.
- 이미지 오른쪽 아래의 남/여 현황: **회차별**로 보여준다.

**[참가하기] 위의 "참가 항목 선택" 영역**
- 항목마다 선택 카드를 하나씩 둔다. 카드에는 이름, 포함 회차와 시간, **내 성별 가격**, 회차별 남은 자리를 보여준다. 로그인하지 않았으면 남/여 가격을 둘 다 보여준다.
- 내 성별 기준으로 포함 회차 중 하나라도 차 있으면, 그 카드는 "마감"으로 표시하고 고를 수 없게 한다.
- 항목을 고르지 않고 [참가하기]나 [장바구니]를 누르면 "참가 항목을 선택해주세요"를 띄운다.
- 고른 항목은 장바구니에 담기고 결제까지 이어진다.

**실시간 참가 인원:** 참가자 이름 옆에 항목 이름을 작게 표시한다(10-2 확정 필요).

### 8-2. 그 밖의 화면

| 화면 | 변경 |
|---|---|
| 메인 카드 | 모든 항목이 마감이면 "모집 마감" 배지(8-3 계산) |
| 일정 섹션 | 파티당 일정 1개(첫 회차 시작 시각). 남은 자리는 회차별로 "1부 남3·여2 · 2부 남5·여4" |
| 마이페이지 장바구니·예약 | 파티 제목 옆에 항목 이름. 장바구니 금액은 항목 가격 기준 |

| 취소 요청 화면 | 항목 이름 표시. 환불액은 지금처럼 실결제액 기준 |

### 8-3. 남은 자리·마감 계산 (참가 구성이 있는 파티)

**파티 단위 숫자(`maleBooked`/`maleStock`)로 마감을 판단하지 않는다.** 파티 단위 인원은 신청 건수이고 대표 정원은 회차 정원의 최댓값이라서, 1부만·2부만 신청자가 섞이면 자리가 남았는데도 마감으로 보인다.
- 예: 1부·2부 남 정원 각 2명. "1부" 1건, "2부" 2건이면 파티 단위로는 남 3/2라서 지금 계산식으로는 남성 마감이다. 실제로는 1부에 1자리가 남았고, 상세 페이지에서 남성 신청이 막힌다.

규칙:
- 계산은 `app/lib/data.ts`의 `partyStockStatus` 한 곳에서 한다. 메인 카드, 일정 섹션, 상세 페이지의 성별 신청 차단 문구가 모두 같은 결과를 쓴다.
- **항목 마감(성별):** 그 항목에 포함된 회차 중 하나라도 그 성별 정원이 찼다.
- **성별 마감:** 그 성별로 고를 수 있는 항목이 하나도 없다.
- **모집 마감:** 남녀 모두 마감이다.
- **마감 임박:** 마감이 아니고, 어느 회차든 남은 자리(남+여)가 1~3석이다.
- 남은 자리 숫자는 회차별로 보여준다(일정 섹션, 상세 상단 현황, 항목 카드).
- 참가 구성이 없는 파티는 지금 계산식을 그대로 쓴다.

## 9. 변경하지 않는 것 (회귀 금지)

## 10. 확정 필요 (기본안으로 개발하고, 바뀌면 반영)

1. **항목 변경(예: 1부 → 1부+2부):** 기본안은 회원이 직접 바꿀 수 없고, 기존 예약을 취소한 뒤 다시 신청하는 것이다(환불 규정 적용). 운영팀이 수동으로 처리하는 경우는 관리자 화면에서 항목만 바꾸는 기능을 나중에 따로 만든다.
2. **실시간 참가 인원 표시:** 기본안은 참가자 이름 옆에 항목 이름을 함께 보여주는 것이다.
3. **쿠폰:** 기본안은 모든 항목에 똑같이 적용하고, 할인은 고른 항목 가격 기준으로 계산하는 것이다.
