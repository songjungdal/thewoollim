## 0. 목적과 결정 사항

로테이션 소개팅 참가자 수준을 높이고, "검증된 사람만 오는 곳"이라는 신뢰를 주기 위해 사진 심사와 직업 인증을 도입한다.

| 항목 | 결정 |
|---|---|
| 사진 심사 | **필수.** 얼굴 사진 2장, 운영진이 눈으로 보고 승인/반려 |
| 인증 시점 | 가입은 지금처럼 바로. **첫 파티 결제 전에 사진 심사 승인 필요** |
| 적용 범위 | 매칭파티·솔로파티 모두. 한 번 승인되면 모든 파티 신청 가능 |
| 사진 용도 | **운영진 심사 + 현장 본인 확인만.** 다른 참가자에게 절대 공개하지 않음 |
| 직업 인증 | **선택.** 인증하면 "직업 인증" 배지 표시 |
| 기존 회원 | 다음 파티 신청(결제) 때 사진 심사를 받아야 함. 이미 결제된 예약은 영향 없음 |

**자동 얼굴 인식·얼굴 대조(AI) 기능은 넣지 않는다.** 사진을 사람이 보고 판단하는 방식이어야 일반 개인정보로 처리할 수 있다. 얼굴 사진을 인증·식별 목적으로 기술적으로 처리하면 개인정보보호법 시행령 제18조 제3호의 민감정보가 되어 별도 동의 등 의무가 생긴다(개인정보보호위원회 2024 개인정보 보호법 해석 사례집). 화면 문구에서도 "얼굴 인증"이 아니라 **"사진 심사"**라는 표현을 쓴다.

## 1. 현재 구현 상태 (코드 확인 결과)

- 가입: 다날 본인인증(`api/auth/verify-identity.php`) → 이메일·비밀번호(`api/register.php`) → 혼인여부(`/onboarding`, `api/onboarding.php`)
- 직업: 프로필 카드(`/profile-setup`, `api/profile.php`)에 **글자로만 입력**. 증빙 없음. 회원이 언제든 수정 가능(보조 5종)
- 신청 흐름: 가입 → 결제 → 프로필 카드 → 운영진 [참가확정]
- 결제 진입 서버 코드: 카드/간편결제 `api/payments/pending.php`, 무통장 `api/payments/vbank-submit.php`
- 파티 상세의 참여자 명단(`api/party-participants.php`)은 성씨 마스킹·나이대·MBTI·직업을 공개함 (솔로파티는 MBTI·직업 빈 값)
- 업로드: 관리자 업로드(`api/admin/upload*.php`)는 전부 웹 루트 안 `/uploads/...`에 저장되어 **주소만 알면 누구나 열 수 있음**
- 비공개 저장 위치: `api/lib.php`의 `privateDataDir()` — 웹 루트 밖 `<웹루트>-data`(운영 기준 `/var/www/thewoollim-data`) 폴더를 조건이 맞을 때만 사용
- 테스트 회원: `isTestUser()` (a1~a20·b1~b20@naver.com)

## 2. 회원 화면

### 2-1. 파티 신청 시 막기 (파티 상세 [신청하기], 결제 화면 진입)

로그인한 회원의 사진 심사 상태에 따라:

| 상태 | 동작 |
|---|---|
| 미제출 | 안내창: **"파티 신청 전, 사진 심사가 필요해요"** / "어울림은 사진 심사를 통과한 분들만 참여하는 검증된 파티입니다. 한 번만 등록하면 모든 파티를 신청할 수 있어요." / 버튼 [사진 등록하기] → `/verification/` (보던 파티 주소를 기억해 승인 후 돌아갈 수 있게) |
| 심사 중 | 안내창: **"사진 심사 중이에요"** / "심사가 끝나면 문자로 알려드릴게요. 승인 후 바로 신청하실 수 있어요." / [확인] |
| 반려 | 안내창: **"사진을 다시 등록해주세요"** / 반려 사유 표시 / [다시 등록하기] |
| 승인 | 지금과 똑같이 진행 |

- 장바구니 담기는 막지 않는다. **결제 단계에서만** 막는다(장바구니→결제 화면 진입 시 같은 안내창).
- 비로그인 상태 동작은 지금 그대로.

### 2-2. 인증 페이지 `/verification/` (로그인 필요, noindex, 사이트맵 제외)

한 페이지에 두 영역. 모바일 375px 기준으로 먼저 만들고 PC는 가운데 정렬 최대 폭(기존 마이페이지와 같은 폭).

**① 사진 심사 (필수)**
- 제목: "사진 2장 등록" / 부제: "운영진만 확인하며, 다른 참가자에게는 공개되지 않습니다."
- 사진 칸 2개
  - 1번 "얼굴 정면 사진": 본인 혼자, 얼굴 전체가 선명하게 보이는 사진
  - 2번 "자유 사진": 본인 얼굴이 보이는 일상·전신 사진
- 등록 기준 안내(작은 글씨 목록)
  - 선글라스·마스크·모자로 얼굴을 가리지 않은 사진
  - 단체 사진, 과도한 보정·필터 사진은 반려될 수 있어요
  - 최근 1년 이내 사진을 권장해요
  - 파티 당일 신분증 확인 때 등록하신 사진과 대조합니다
- 동의(필수, 미리 체크 금지): "[필수] 사진 수집·이용 동의 [보기]" — 7장 문구
- 버튼 [심사 요청하기] (사진 2장 + 동의 체크 시 활성)
- 제출 후 화면: "심사 요청이 접수되었어요. 결과는 문자로 알려드릴게요."

**② 직업 인증 (선택)**
- 제목: "직업 인증 (선택)" / 부제: "인증하면 파티 참여자 명단에 '직업 인증' 배지가 표시돼요. 제출 서류는 확인 후 바로 삭제합니다."
- 구분 선택: [직장인] [사업자] [기타(전문직·프리랜서 등)]
- 직장인: 아래 중 1개 업로드
  - 재직증명서 / 명함 / 사원증 / 건강보험 자격득실확인서
- 사업자: 사업자등록증 업로드 + 사업자등록번호 10자리 + 개업일자 입력
- 기타: 자격증, 위촉·용역계약서 등 직업을 확인할 수 있는 서류 1개
- **빨간 안내문(필수 노출): "주민등록번호 뒷자리는 반드시 가리고 올려주세요. 가려지지 않은 서류는 반려 후 즉시 삭제됩니다."**
- 동의(선택 항목이지만 제출하려면 체크 필요): "[선택] 직업 증빙 서류 수집·이용 동의 [보기]"
- 버튼 [직업 인증 요청하기]

### 2-3. 마이페이지

- "인증 관리" 카드 추가: 사진 심사 상태(미제출/심사 중/승인/반려+사유), 직업 인증 상태(미인증/심사 중/인증 완료+표시 직업/반려+사유)

### 2-4. "직업 인증" 배지

- 위치: 파티 상세 참여자 명단의 직업 옆 (작은 체크 배지 + "직업 인증")
- 매칭파티만 표시 (솔로파티는 지금처럼 직업 자체를 공개하지 않으므로 배지도 없음)
- 직업 인증 승인 후 회원이 프로필 카드의 **직업 글자를 바꾸면 배지를 숨기고** 상태를 "재인증 필요"로 바꾼다 (인증한 직업과 공개 직업이 달라지는 것 방지)
- 배지 디자인은 기존 브랜드 포인트 색(`brand-point`)과 기존 배지 크기·모양을 따른다

## 3. 서버

### 3-1. 결제 진입 검사 (핵심)

- `api/payments/pending.php`, `api/payments/vbank-submit.php`에서 회원 확인 직후 사진 심사 상태 검사
  - 승인 아님 → `403`, `{ ok:false, error:"사진 심사 승인 후 파티를 신청할 수 있습니다.", code:"PHOTO_REQUIRED" }` (code는 미제출/심사중/반려 구분: `PHOTO_REQUIRED` / `PHOTO_PENDING` / `PHOTO_REJECTED`)
- 테스트 회원(`isTestUser`)은 검사 통과
- 위 두 곳 외에 회원이 예약을 만드는 다른 경로가 있으면(멤버십 예약 등) 모두 찾아 같은 검사를 넣고, 찾은 경로 목록을 PR 설명에 적는다
- 관리자가 직접 예약을 만드는 경로는 검사하지 않는다
- 화면 검사만으로는 안 됨. **서버 검사가 기준**

### 3-2. 업로드 API (신규)

- `POST /api/verification/photo.php` — FormData `photo1`, `photo2`, `agree=1`
- `POST /api/verification/job.php` — FormData `type`(employee|business|other), `docKind`, `file`, 사업자면 `bizNo`, `openDate`, `agree=1`
- `GET /api/verification/state.php` — 본인 상태만 반환(파일 경로는 반환하지 않음)
- `GET /api/verification/my-photo.php?slot=1|2` — 본인 사진 미리보기(본인 세션 확인)
- 공통
  - 회원 세션 필수, 본인 것만
  - JPG/PNG/WEBP만, 파일당 10MB 이하, `finfo`로 MIME 검사 (기존 `api/admin/upload.php` 방식)
  - **서버에서 이미지를 다시 저장(재인코딩)해 EXIF(촬영 위치 GPS 등) 제거**, 긴 변 1600px로 축소. 서버에 GD/Imagick이 있는지 확인하고, 없으면 PR에 적고 대안 제시
  - iPhone 사진(HEIC)은 화면에서 JPEG로 변환해 올린다(브라우저 canvas). 변환 실패 시 "JPG로 저장해서 올려주세요" 안내
  - 파일명은 서버가 무작위로 생성
  - 같은 회원이 짧은 시간에 반복 업로드 못 하게 제한(예: 10분에 5회)

### 3-3. 사업자 확인 (국세청)

- 공공데이터포털 "국세청_사업자등록정보 진위확인 및 상태조회 서비스" 사용
  - 진위확인: 사업자번호 + 개업일자 + **대표자 성명(= 본인인증 이름)** → 회원 본인이 대표인지 확인
  - 상태조회: 계속사업자/휴업/폐업
- 인증키는 서버 설정 파일(기존 `*-config.example.php` 방식)에만. 화면·저장소·로그 노출 금지
- 결과는 관리자 심사 화면에 참고로 표시(자동 승인하지 않음). 인증키가 없거나 호출 실패 시 "자동 확인 불가 — 서류로 판단" 표시하고 수동 심사로 진행
- 참고: 국세청 정보는 30분 주기로 갱신되고 신규 개업자는 1~2일 걸릴 수 있으므로, 조회 실패만으로 반려하지 않는다

### 3-5. 파일 저장·보관·삭제

- 저장 위치: **`privateDataDir()` 아래 `verification/`** (웹 루트 밖). 폴더 권한은 웹 서버 사용자만 읽기·쓰기
- `privateDataDir()`가 `null`(웹 루트 밖 폴더 없음)이면 **업로드를 거절**하고 오류 기록. 웹 루트 안(`api/data/`, `uploads/`)으로 대체 저장 금지
- 배포 rsync 필터에 이 폴더가 덮어쓰기·삭제되지 않는지 확인(웹 루트 밖이라 대상이 아니어야 함)
- 보관 기간
  - 사진(승인): 탈퇴 시까지. 탈퇴 처리(`api/delete-account.php`, 관리자 회원 삭제)에서 즉시 파일 삭제
  - 사진(반려·대체됨): 30일 후 삭제 (기존 cron 방식에 정리 작업 추가)
  - **직업 서류: 승인/반려 처리 즉시 파일 삭제.** 기록(종류·결과·표시 직업·처리자·일시)만 남김
  - 주민등록번호가 가려지지 않은 서류: 반려 시 즉시 삭제(위 규칙과 동일)

## 4. 관리자 대시보드

### 4-1. 새 탭 "인증 심사"

- 목록: 심사 중을 먼저, 오래된 순. 필터: 사진/직업, 상태
- 각 줄: 이름, 성별, 나이, 혼인여부, 가입일, 참가 이력 수, 제출 일시
- 상세 보기
  - 사진: 2장 크게 (관리자 인증 API로만 불러옴, `api/admin/verification-file.php`), 이전 승인 사진이 있으면 나란히
  - 직업: 서류 이미지, 구분·서류 종류, 사업자는 국세청 조회 결과
  - 버튼: **[승인]** / **[반려]**
  - 반려 사유 선택: "얼굴이 잘 보이지 않음", "본인 사진이 아닌 것으로 보임", "단체 사진", "과도한 보정·필터", "주민등록번호 미가림"(직업), "서류로 직업 확인 불가"(직업), "기타(직접 입력)"
  - 직업 승인 시 "표시 직업" 입력 필수 (기본값: 회원 프로필의 직업)
- 모든 열람·승인·반려를 기존 로그 관리에 기록 (누가 언제 누구의 사진/서류를 봤는지)
- 대시보드 첫 팝업 "확인할 업무"에 "인증 심사 대기 N건" 추가
